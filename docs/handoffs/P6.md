## 5. Interfaces and contracts the next phase must preserve
- **Deliberately changed assertions and tests:** (1) `client/test/hud.test.ts` expects the keys line "Hold Q ping / Tab team" instead of the "(soon)" placeholders (A). (2) `server/test/death/gateway.test.ts`, `death/review.gateway.test.ts` and `social/gateway.social.test.ts` now create the server with `devFlags: true`, because `?ghost=N` is a dev flag that is refused otherwise (C). Nothing else in an old test changed.
- Protocol is additive: `ping:place`, `chat:send`, `run:choose` (client to server); `ping:marker`, `chat:message`, `team:panel`, `profile:state` (server to client). Handshake `auth.token` (or the `wb_session` httpOnly cookie) carries the session token.
- `Room`: `restoreRun(save, hostHighest)` (lobby only; refuses a save ahead of the host's progress or in a locked mode), `newRun()`, `setHostFloor`, `unlockBasis` (also the lobby snapshot's `highestStage`), `drainClears`, `drainSaveUpdates`, `varietyRecords`/`restoreVariety` (unchanged). `runSeed` is now mutable (a restore sets it). The save points at the NEXT stage; `highestStage = cleared + 1`.
- `ProgressStore` is the only persistence; `ProgressService` is what the game calls (never the store directly). Writes are compare-and-set on the account version; highest stage is a monotone max.
- A guest earns and stores nothing. A down store means guest-like play and a lobby message.
- Stages are endless; the guard test `no-final-stage` forbids names like `MAX_STAGE` (use `STAGE_NUMBER_LIMIT`-style names for schema bounds).
- `test/death/solve` and `test/death/revive.gen` stayed green; spectators still see only ghosts and teammates; reviews name no code, safe or door.

## 6. Known bugs and incomplete work
- **Workstream B not built** (see top).
- **Real mid-run reconnect is not built:** the room only lets players join in the lobby and drops disconnected players at the next stage. The session token keeps a reconnecting socket signed in, but it re-enters the lobby, not its old seat.
- Signing in or out in the lobby rebuilds the lobby (the socket reconnects with or without the token) and rejoins by the room code in the URL; if the person was alone in the room as its host, that room no longer exists afterwards.
- The save is written to whoever hosts at the moment of the clear (a host change mid-run writes to the new host's slot, replacing theirs).
- A Hardcore wipe's lost upgrade is not saved (Continue returns to the last clear).
- `node:sqlite` is marked experimental by Node and prints a warning; it needs Node 22.5+. It also needs a persistent disk; a multi-instance deployment needs a shared disk or another `ProgressStore`.
- Team chat has no lobby UI (the server accepts lobby chat). Pings are not re-sent on reconnect.
- Account creation has no email recovery by design: losing the provider account loses the progress.
- The dev sign-in uses `window.prompt` (dev only).
